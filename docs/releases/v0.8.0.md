# 0.8.0

**Breaking.** This is a breaking release. Tracking issue: [#40](https://github.com/dfkunstler/mcp-server-for-oscal/issues/40).

## Highlights

- **29 tools replaced by 3.** `list_documents`, `query_documents`, and `list_child_elements` take the model or element type as an argument. They replace the per-model `query_*` and `list_*` tools and the three Component Definition list tools.
- **Lighter on your assistant's context.** The `tools/list` response shrinks from 34,938 to 18,391 characters, and from 46 to 20 entries.
- **A hard break.** If you use the server only through an AI assistant (Claude, Kiro, and so on), there is nothing to do: the assistant reads the new tool definitions automatically. If you call the removed tools from scripts, or have prompts that name them, read [Breaking changes](#breaking-changes) before upgrading.

## Breaking changes

The 29 tools in the table below are removed. No aliases and no compatibility flag exist: a call to a removed tool name fails with an unknown-tool error. Switch to the replacement and pass the fixed arguments from the last column. All other arguments (`query_type`, `query_value`, `parent_doc_uuid`, `offset`, `limit`) pass through unchanged.

### Result key renames for the Component Definition listers

The three replaced Component Definition tools (`list_component_definitions`, `list_components`, `list_capabilities`) return items with new key names:

- `componentCount` is now `childCount`.
- `uuid` is now `id` (component and capability items).
- `name` is now `title`.
- `parentComponentDefinitionTitle` is now `parentDocumentTitle`.
- `parentComponentDefinitionUuid` is now `parentDocumentUuid`.

### Behavior changes

- `childCount` counts Components plus Capabilities. The old `componentCount` already did, and its name hid that.
- `importedComponentDefinitionsCount` was the literal 0 for every item, regardless of the document. It carried no information and has no replacement.
- On an empty store, the listers return an empty page. The old `list_component_definitions` and `list_components` raised a `RuntimeError`.
- Child items gain `sizeInBytes` (the 12 per-model child listers did not return it), `element_type`, and `description` (the old Component and Capability listers did not return them).
- Document items from `list_documents` with `model_type="component-definition"` gain `model_type`.
- `offset` and `limit` are now checked: `offset` must be 0 or more, and `limit` must be from 1 to 100. Out-of-range values are rejected with an error. The old per-model tools passed them to SQLite unchecked.
- `query_documents` and `list_documents` accept `model_type="component-definition"`. The old per-model query tools had no Component Definition document lookup.

## Measurements

- `tools/list` characters: Before_Size 34,938 (main at 599a41d), After_Size 18,391 (0.8.0).
- `tools/list` entries: 46 before, 20 after.
- Registry tools (without `about`): 45 before, 19 after.

Environment: Python 3.14.8, `mcp` 2.1.1.

Measurement command: `hatch run python bin/export_tools_list.py <out.json>`, field `toolsListChars`. For the Before value, run it on a worktree of 599a41d with `PYTHONPATH=<worktree>/src`.

The requirements text quotes 55,685 characters. That figure was measured before 0.6.3, and the `BASELINE_SIZE` constant in `tools/tool_budget.py` is stale history. The Before value above is the size at the start of this change.
